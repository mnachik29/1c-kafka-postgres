# 1С: подготовка тестовой базы и публикация OData

Платформа: **1С:Предприятие 8.3.25 или новее**, файловая информационная база (режим совместимости 8.3.25).
Подойдёт учебная версия или комьюнити-лицензия.

Проверенная связка: платформа **8.3.27.2342 x86** с модулями веб-сервера + **Apache 2.4.69 Win32**
(Apache Lounge, VS18), служба `Apache2.4`, публикация `/demo1c`.

> Модуль `wsap24.dll` должен совпадать с Apache по разрядности: 32-битная платформа — 32-битный Apache,
> x64 — Win64. Пока база открыта веб-сервером, пакетные запуски `1cv8.exe /C …` возможны только
> платформой той же версии. Иначе 1С ответит «Существуют активные сеансы … другой версии». В этом случае
> меняйте данные в клиенте той же версии или через OData PATCH (`scripts/odata-demo.sh`).

## Что лежит в каталоге

| Путь | Что это |
|---|---|
| `src/` | Конфигурация в XML-выгрузке (формат 2.18) — исходник, удобный для git/review |
| `configuration.cf` | Та же конфигурация, файл для «Загрузить конфигурацию из файла» |
| `configuration.dt` | Выгрузка информационной базы с тестовыми данными |
| `default.vrd` | Шаблон публикации на веб-сервере с включённым стандартным OData |
| `odata-mock/` | Эмулятор OData 1С (запасной вариант, если нет модулей веб-сервера) |
| `screenshots/` | Скриншоты настройки |

## Конфигурация «ИнтеграцияДемо»

**Справочник `ФормыСобственности`**: Код, Наименование, ПометкаУдаления (стандартные) + реквизит
`ДатаИзменения` (Дата и время, индексируется).

**Справочник `Контрагенты`**: Ссылка (UUID), Код, Наименование, ПометкаУдаления (стандартные) +
`ИНН` (Строка 12), `КПП` (Строка 9), `ФормаСобственности` (СправочникСсылка.ФормыСобственности),
`ДатаИзменения`.

**Модуль объекта** обоих справочников: в `ПередЗаписью` реквизит `ДатаИзменения` получает
`ТекущаяУниверсальнаяДата()`. Так у каждой записи есть метка изменения в UTC, в том числе при
установке и снятии пометки удаления. По ней integration-service делает инкрементальную выгрузку.

**Общий модуль `ДемоСервер`** и **модуль управляемого приложения** нужны для служебных команд,
которые запускаются в пакетном режиме через параметр `/C`:

| `/C` | Действие |
|---|---|
| `init` | `odata` + `seed` |
| `odata` | `УстановитьСоставСтандартногоИнтерфейсаOData` — публикует оба справочника в OData |
| `seed` | 4 формы собственности (ООО, ИП, АО, ПАО) и 6 контрагентов; повторный запуск ничего не дублирует |
| `demo-update` | меняет КПП у «ООО «Ромашка»» (770101001 ⇄ 770101002) |
| `demo-delete` / `demo-restore` | ставит или снимает пометку удаления у «ООО «Лютик»» |

## 1. Создание базы

Вариант А — скриптом (создаёт `1c\ib`, загружает `src`, выполняет `init`):

```powershell
.\scripts\1c.ps1 create
```

Вариант Б — вручную:

```powershell
$v8 = "C:\Program Files\1cv8\8.3.25.1394\bin\1cv8.exe"
& $v8 CREATEINFOBASE File="C:\path\to\repo\1c\ib"
& $v8 DESIGNER /F "C:\path\to\repo\1c\ib" /LoadConfigFromFiles "C:\path\to\repo\1c\src" /UpdateDBCfg
& $v8 ENTERPRISE /F "C:\path\to\repo\1c\ib" /C init
```

Вариант В — через интерфейс: создать пустую базу, затем Конфигуратор → Администрирование →
Загрузить информационную базу → `configuration.dt` (база сразу с данными). Или
Конфигурация → Загрузить конфигурацию из файла → `configuration.cf`, после чего один раз запустить
`/C init`.

## 2. Публикация на веб-сервере (OData)

1. Установите компонент **«Модули расширения веб-сервера»**: запустите установщик платформы →
   «Изменить» → отметьте компонент. Проверка — в `C:\Program Files\1cv8\<версия>\bin` должны появиться
   `wsap24.dll` и `webinst.exe`.
2. Установите Apache 2.4 той же разрядности, что и платформа (сборка Apache Lounge, распаковать в `C:\Apache24`) и зарегистрируйте его как
   службу: `httpd -k install`. Подойдёт и IIS.
3. Опубликуйте базу. Нужны права администратора, т.к. правится `httpd.conf`:
   ```powershell
   .\scripts\1c.ps1 publish
   ```
   Или вручную: Конфигуратор → Администрирование → Публикация на веб-сервере → имя `demo1c`,
   флажок **«Публиковать стандартный интерфейс OData»**. В `default.vrd` должна появиться строка
   `<standardOdata enable="true" .../>`.
4. Выдайте учётной записи службы Apache права на изменение каталога `1c\ib` и перезапустите Apache.
5. Проверьте:
   ```
   http://localhost/demo1c/odata/standard.odata/$metadata
   http://localhost/demo1c/odata/standard.odata/Catalog_Контрагенты?$format=json
   ```

В базе нет пользователей, поэтому OData работает без аутентификации. Если пользователи появятся,
укажите `ONEC_USER` и `ONEC_PASSWORD` в `.env`: integration-service передаёт их через Basic-авторизацию.

## 3. Как integration-service читает данные

```
GET /demo1c/odata/standard.odata/Catalog_Контрагенты
    ?$format=json
    &$select=Ref_Key,Code,Description,ИНН,КПП,ФормаСобственности_Key,DeletionMark,ДатаИзменения,DataVersion
    &$orderby=ДатаИзменения,Ref_Key
    &$top=500&$skip=0
    &$filter=ДатаИзменения ge datetime'2026-07-10T12:00:00'      ← только в инкрементальном режиме
```

Из контейнера 1С доступна по адресу `http://host.docker.internal/demo1c/odata/standard.odata`
(значение по умолчанию в `.env.example`).

## Если модули веб-сервера поставить нельзя

Включите эмулятор, который повторяет используемое подмножество OData 1С (те же имена наборов и полей,
та же логика `ДатаИзменения`):

```
COMPOSE_PROFILES=mock
ONEC_ODATA_URL=http://onec-mock:8080/demo1c/odata/standard.odata
```

Данные в эмуляторе меняются через PATCH, как и в настоящем OData 1С: `scripts/odata-demo.sh update|delete|restore`.
